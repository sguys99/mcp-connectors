# 섹션별 질문 뱅크 (AskUserQuestion 표준 세트)

각 섹션에서 사용할 AskUserQuestion 호출 예시. `multiSelect`는 옵션 성격에 맞게 조정. 사용자가 자유 입력하기 어려운 항목은 옵션화하고, 그 외는 단답형 텍스트를 받는다.

> **공통 원칙**
> - 한 번에 1~4개 질문. 너무 많으면 4개씩 끊어 여러 번 호출.
> - 사용자가 "모르겠다/확인 필요"라고 답하면 정의서에 `**확인 필요 (X팀 회신 대기)**` 표기로 남김 (영어 정의서는 `**TBD (waiting for X team)**`) ([예시 4.2](example_code_repo.md#42-연동-백엔드-시스템) 참조).
> - 사용자가 답을 직접 텍스트로 주는 경우, AskUserQuestion 대신 그냥 받아 적는다.

---

## 시작 전. 작성 언어

요청 문장으로 언어를 정합니다. 사용자가 언어를 명시했으면("영어로", "in English", "한국어로") 그대로 따르고, 영어로 요청했으면 영어로 씁니다. 한국어 요청인데 공개 저장소용이거나 해외 팀과 공유한다는 말이 있으면 첫 AskUserQuestion 묶음에 다음 질문을 하나 넣습니다.

```
질문: "정의서를 어떤 언어로 작성할까요?"
- [한국어 (Recommended)] template_v2.md, 한국어 작성 규칙 적용
- [English] template_v2.en.md, 헤딩과 표 구조는 동일
```

이후 인터뷰 질문도 정한 언어로 묻습니다. 아래 질문 문구는 한국어 기준이므로 영어로 진행할 때는 옮겨서 씁니다.

---

## §0~1. 문서 정보 + 개요

```
질문 1: 서버 식별 정보
- "서버명 (kebab-case로, 예: code-repo-mcp, oracle-db-mcp): ?"
- "작성자 / 소속: ?"
- "한 줄 소개 (어떤 백엔드와 어떤 Agent를 연동해서 무엇을 지원하는지): ?"
* 자유 입력 (텍스트)

질문 2: 목적, 배경, 기대효과 (한 번에 묶어 받음)
- 목적: 왜 만드는가
- 배경: 현재 어떤 문제/한계가 있는가
- 기대 효과: 가능하면 정량적으로 (예: 리뷰 시간 30% 단축)
* 자유 입력 (3개 항목)
```

---

## §2. 범위

```
질문: 포함 범위와 제외 범위
- "이 MCP가 제공할 기능 (조회/생성/검색 등): 자유 서술"
- "이 MCP가 처리하지 '않을' 부분 (오해 방지): 자유 서술"
```

옵션 예시 (백엔드별 기본 포함 후보):
- 코드 저장소: PR/Commit/File/Branch 조회, diff 추출, 영향도 분석 보조
- DB: 메타데이터 조회, 스키마 조회, 샘플 행 조회, 쿼리 실행
- DW: 카탈로그 조회, 컬럼 통계, 쿼리 실행, 사용량 조회

제외 범위 기본 후보:
- 쓰기 작업 (PR Merge/Approve, INSERT/UPDATE/DELETE)
- 권한 변경, 사용자 관리
- 백엔드 외 타 시스템 연동

## §3. 사용자 및 시나리오

```
질문 1: 사용 Agent
- "호출 Agent 이름: ?"
- "예상 호출 빈도 (1일 N회, 피크 분당 N): ?"
- "동시 세션: ? (PoC 기준)"
- "호출 성격": [읽기 100% / 읽기 위주 / 읽기-쓰기 혼합]

질문 2: Use Case 도출
- "대표 시나리오 2~4개 (UC-01, UC-02 ...)"
- 각 시나리오 한 줄 + 어떤 Tool을 쓸지 (5장과 매핑)
```

## §4. 시스템 구성

```
질문 1 (4.1 MCP 서버):
- Transport: [Streamable HTTP (Recommended) / STDIO / SSE]
- 배포 환경: [Kubernetes / Docker / VM / 내부 인프라(상세 미정)]
- 엔드포인트: 자유 입력 (미정이면 후보 + "예정" 표기)

질문 2 (4.2 백엔드 시스템):
- 시스템명: 자유 입력
- 종류: [코드 저장소 / RDB / DW / 메타정보 / API / 기타]
- 엔드포인트: 자유 입력 (미정이면 "확인 필요")
- 프로토콜: [HTTPS REST / gRPC / JDBC / Native SDK / 미정]
- 인증 방식: [PAT / OAuth / Kerberos / DB 계정 / 내부 SSO / 미정]
- 네트워크: 내부망 여부, VPC, 방화벽 메모
- 참고 문서 URL: 자유 입력
```

## §5. Tool 명세 (핵심)

### 5-A. Tool 목록 도출 (반복 루프 진입 전)

```
질문: "어떤 Tool을 제공할지 목록을 함께 정리해봅시다."
- UC와 매핑하여 Tool 이름 후보 제시 (snake_case)
- 예시:
  - UC-01 'PR 변경 요약 조회' → get_pr, get_file_diff
  - UC-02 '파일 참조 검색' → search_references
- 사용자가 추가/수정/삭제 의견 받음
```

도출 후 5.1 요약 표를 먼저 채우고, 그다음 5.2를 Tool별로 루프.

### 5-B. Tool 1건당 상세 (LOOP)

각 Tool마다 다음을 순차 질문:

```
질문 1: 사람용 설명 + LLM Description
- "Tool 이름 확정: ?"
- "사람용 한 줄 설명: ?"
- "LLM Description (3~7줄, 다음 4요소 포함):
   1) 이 Tool이 무엇을 하는가
   2) 언제 호출해야 하는가
   3) 언제 호출하지 말아야 하는가 (대체 Tool 안내)
   4) 호출 예시 한 줄 (자연어 → Tool 호출)"

질문 2: 입력 파라미터
- 표 형식: 이름 / 타입(string|int|bool|ISO8601|enum) / 필수(Y/N) / description
- 모든 파라미터에 description 필수 (Agent 노출됨)

질문 3: 출력 JSON
- 정상 응답 예시 1건 (실제 값으로, example_code_repo 예시 수준의 디테일)
- 빈 결과 정의 (예: "files_changed: []")
- 응답 크기 제어: limit 최대값 / cursor / *_TOO_LARGE 트리거

질문 4: 에러 응답
- 최소 다음 3종은 정의:
  - *_NOT_FOUND (리소스 없음)
  - ACCESS_DENIED (권한)
  - INVALID_INPUT (입력 오류)
- 각각 자연어 메시지 (원인 + 조치 포함)
- 백엔드 장애: BACKEND_UNAVAILABLE / TIMEOUT
- 도메인 특화: FILE_TOO_LARGE, DIFF_TOO_LARGE, INVALID_REGEX 등
```

### 5-C. 루프 종료

```
질문: "추가할 Tool이 더 있나요?"
- [있음, 다음 Tool 정의 → 5-B로]
- [없음, 5장 종료]
```

## §6. 비기능 요구사항

```
질문 1 (성능):
- P95 응답시간 목표 (초): 기본 < 2초
- 동시 처리 건수: 기본 5
- 단일 응답 크기 한도: MB / 토큰 양측 (기본 5MB / 32K 토큰, 일반 Tool은 1MB / 8K)

질문 2 (보안):
- MCP 인증 방식: [API Key 헤더 / mTLS / OAuth / 내부 SSO]
- 백엔드 자격증명 저장: [Vault / 시크릿 매니저 / 환경변수 / 미정]
- 백엔드 계정 권한: [Read-only / Read-write] (PoC는 Read-only 강력 권장)
- 인가 경계: Agent별 권한 매핑 필요 여부
- 민감정보 마스킹 대상: [주민번호 / 카드번호 / 사번 / 이메일 / 자유]

질문 3 (로깅):
- 수집 시스템: [Splunk / ELK / Datadog / 내부 시스템명 / 미정]
- 보존 기간: 기본 90일
- 민감정보 처리: 입력 파라미터 해시 처리
```

---

## §7. 에러 처리

```
질문:
- 백엔드 호출 Timeout: 기본 5초 (검색류는 10초)
- 재시도 정책: 5xx 시 1회 (Exponential Backoff)
- Circuit Breaker 도입 여부: [Y/N]
  - Y면 임계치 (예: 10초 내 5회 실패 → 30초 차단)
```

## §8~10. 산출물 / 일정 / 인수 기준

```
질문 1 (산출물):
- 다음 중 포함할 산출물 선택 (multiSelect):
  - 소스 저장소 URL 및 접근 권한
  - Tool 명세서 (Markdown 및 MCP standard schema)
  - 설치/실행/운영 가이드 (Docker 이미지)
  - 단위/통합 테스트 코드 및 결과서
  - LLM Tool-calling 평가셋 (10건 이상) 및 통과율 결과서
  - 백엔드 인터페이스 매핑 문서
  - 운영 모니터링 대시보드

질문 2 (일정):
- 요구사항 확정일 (v1.0): 자유 입력
- 개발 완료일: 자유 입력
- (있으면) 백엔드 인터페이스 검증 완료일: 자유 입력
- 통합 테스트 / UAT 기한: 자유 입력
- 운영 이관일: 자유 입력

질문 3 (인수 기준):
- 5장 정의 Tool 전건 동작 확인
- 6.1 성능 목표 충족 (부하 테스트 결과서)
- 6.2 보안 요건 충족
- LLM Tool-calling 평가셋 통과율 기준 (기본 ≥ 90%)
- 사용자 추가 의견
```

## 종료 후: 검토 및 저장

```
검토 질문:
- 작성된 정의서를 섹션별 한 줄 요약으로 제시
- "이대로 저장할까요? 수정할 섹션이 있으면 번호를 알려주세요"
- 수정 요청 시 해당 섹션만 재질문

저장 질문:
- "저장 경로 (기본: docs/mcp-spec/<server-name>_v0.1.md): ?"
- 경로 확정 → Write
```

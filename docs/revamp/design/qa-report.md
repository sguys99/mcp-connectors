# Phase 3 시안 QA 보고서 (3-5)

> 상태: 3-5 각 시안 라이트/다크, 모바일 폭(390px) 확인 (2026-10-22). 대상은 시안 A Console, 시안 B Studio, 시안 C Workbench, 토큰 미리보기(tokens.html)입니다. comparison.html은 범위에서 뺐습니다.

## 1. 요약

- 검사 상태 420개(시안 3개 x 폭 5 x 테마 4 x 언어 2 x 화면 3, tokens.html은 폭 5 x 테마 4 x 시안 탭 3)를 자동으로 돌렸습니다.
- 수정 전에는 420개 중 362개가 실패했고, 수정 후에는 420개 모두 통과합니다. 포커스 이동 검사 16회도 모두 통과합니다.
- 결함 19건을 찾아 모두 고쳤습니다. 심각도별로 높음 4건, 중간 12건, 낮음 3건입니다.
- 토큰 블록(`@tokens:start` ~ `@tokens:end`)은 네 파일 모두 손대지 않았습니다(HEAD와 해시 동일). 토큰 자체 문제는 없어서 tokens.css도 바꾸지 않았고, `check_contrast.py`는 480쌍 모두 통과합니다.
- 시안의 콘셉트와 레이아웃 정체성은 그대로 두고 결함만 고쳤어요. 고친 자리에는 CSS 주석 `QA 3-5`를 남겼습니다.

## 5. 검사 방법

### 재현 명령

저장소 루트에서 실행합니다. Playwright와 axe-core는 `frontend/node_modules`에서 불러오므로 저장소 package.json은 바꾸지 않습니다.

```bash
# 전체 매트릭스 (약 75초)
node docs/revamp/design/scripts/qa_check.mjs --out "$TMPDIR/mcpc-qa"

# 일부만: 시안 A, 390px, 다크, 스크린샷 생략
node docs/revamp/design/scripts/qa_check.mjs --out "$TMPDIR/mcpc-qa" --files a --widths 390 --themes dark --no-shots

# 토큰 대비 검사
python3 docs/revamp/design/scripts/check_contrast.py
```

옵션은 `--files a,b,c,t`, `--widths`, `--themes light,dark,system-light,system-dark`, `--langs en,ko`, `--no-shots`, `--no-axe`, `--concurrency N`입니다. 실패가 하나라도 있으면 종료 코드 1을 돌려줍니다. 결과 상세는 `<out>/results.json`, 스크린샷은 `<out>/<시안>-<화면>-<폭>-<테마>-<언어>.png`로 남습니다. 스크린샷 폴더는 저장소 밖(스크래치 디렉터리)으로 지정해 주세요.

### 스크립트가 하는 일

1. 시안 HTML 앞에 `<!doctype html>`, charset, viewport 메타를 붙인 사본을 만들어 엽니다(Artifact 게시 때 감싸는 형태와 같음).
2. 페이지 로드 전에 localStorage로 테마(`mcpc-theme`, tokens.html은 `mcpc-tokens-theme`)와 언어(`mcpc-lang`, C는 `mcpc-c-lang`)를 넣고, 시스템 모드는 속성 없이 `colorScheme`만 바꿉니다. 로드 후 `data-theme`과 `lang` 값이 기대와 같은지 확인합니다.
3. 화면마다(`#dashboard`, `#inspector`, `#chat`, tokens.html은 `#console`, `#studio`, `#workbench`) 다음을 검사합니다.
   - 가로 넘침: `scrollWidth > innerWidth`
   - 콘솔 에러와 pageerror
   - 잘림: 뷰포트 밖으로 나간 텍스트나 컨트롤, `overflow: hidden` 조상에 가려진 요소(말줄임 줄은 제외), 클리핑 없이 넘쳐 옆 패널에 겹치는 flex 행(spill)
   - 말줄임 없는 텍스트 잘림: `scrollWidth > clientWidth`, overflow hidden, `text-overflow`가 ellipsis가 아닌 경우
   - 대비: 텍스트가 있는 요소마다 계산된 색과 실제 배경(조상 배경을 합성, 투명도 반영)을 canvas로 sRGB 변환해 WCAG 대비를 계산합니다. 기준은 4.5:1, 큰 텍스트(24px 이상 또는 18.66px 이상 굵게)는 3:1입니다
   - 겹친 컨트롤: 스크롤 조상으로 잘린 가시 영역끼리 비교하고, 고정 바 아래로 지나가는 내용은 제외합니다
   - 390px 터치 대상 24px 미만(WCAG 2.5.8), 문장 안 인라인 링크 제외
   - 접근 이름 없는 아이콘 전용 버튼, id 없는 폼 컨트롤
   - axe-core 4.11 주입 후 `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` 규칙 위반
4. 별도로 390px과 1280px, 라이트와 다크에서 Tab을 최대 70번 눌러 포커스된 요소마다 outline 또는 box-shadow가 있는지, 화면 밖으로 가로로 밀려난(숨은 드로어 안) 요소가 아닌지 확인합니다.

### 육안 확인

자동 검사와 별개로 스크린샷을 직접 보며 정렬, 고아 항목, 과밀, 다크 면의 탁함, 보조 텍스트 대비를 확인했습니다. H4(도구 탭 겹침), M10(한국어 어절 중간 줄바꿈), M11(도구 이름 끊김), M12(Reset 고아 줄바꿈), L3(버튼 세로 쌓임)은 육안으로 찾은 뒤 자동 검사에 해당 규칙을 보강하거나 수정 후 다시 스크린샷으로 확인한 항목입니다.
